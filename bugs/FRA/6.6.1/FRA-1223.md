# FRA-1223: [Android] Parsing error is not handled well for favorite recipes pagination

## Steps to Reproduce
1. Login with a user that has a large number of favorite recipes
2. Navigate to the Recipes section
3. Open the Favorite Recipes list
4. Scroll down to trigger pagination (load more recipes)
5. Mock the pagination endpoint to return a malformed/invalid JSON response

## Expected Result
- The app should handle the parsing error by showing an error state and keeping the old pages loaded.

## Actual Result
- The parsing error from the pagination response is not handled properly. The app shows a general error state and hides all the previous pages

## Verification
| Field | Value |
|-------|-------|
| Status | fail |
| Date | 2026-03-26 |
| Agent | claude-appium |
| Result | Bug confirmed — malformed page 2 response causes full-screen error, hiding all previously loaded recipes |

### Attempt 3 (2026-03-26) — Appium + Proxyman (20+ favorites)
- Device: Samsung Galaxy S22+ (SM-S906B, Android 14)
- App: dk.iroots.rema1000.staging
- Proxyman: Map Local rule #2 enabled for `*/favorite-recipes?include=instructions&per_page=20&page=2` (malformed JSON)
- Step 1: User already logged in on device — skipped login
- Step 2: Tapped "Opskrifter" in bottom nav bar — navigated to Recipes screen successfully
- Step 3: Tapped bookmark icon — "Gemte opskrifter" screen opened, skeleton placeholders appeared
- Step 4+5: Page 1 loaded (20+ favorites now), app automatically requested page 2. Proxyman returned malformed JSON for page 2.
- **Result: Full-screen error state appeared — "Oops - Noget gik galt. Prøv venligst igen." with a "Prøv igen" button. ALL page 1 recipes were hidden.**
- Verdict reasoning: The bug is confirmed. When the pagination endpoint (page 2) returns malformed JSON, the app replaces the entire recipe list with a generic error screen instead of keeping the already-loaded page 1 recipes and showing a localized error (e.g., retry footer or toast).

### Attempt 2 (2026-03-26) — Appium + Proxyman (14 favorites)
- Proxyman page 2 mock enabled but account only had 14 favorites (< per_page=20). Pagination never triggered.

### Attempt 1 (2026-03-25) — Appium only
- Account had ~11 favorites. Pagination not triggered. No Proxyman available.
