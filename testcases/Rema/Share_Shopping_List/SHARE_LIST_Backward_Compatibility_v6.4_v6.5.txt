COMPAT-01 | v6.4 user shares with v6.5 user - Auto-accept legacy flow
    Preconditions
        User A is on app version 6.4.x (logged in, has active shopping list)
        User B is on app version 6.5 (logged in)
    Actions
        User A opens their shopping list
        User A taps "Share" and generates a share link
        User A sends the share link to User B
        User B opens the share link in their v6.5 app
    Expected
        User B's invitation is auto-accepted using the v6.4 sharing mechanism
        User B immediately sees User A's shopping list in their lists
        User B can view and edit items in the shared list
        Both users see the same items and real-time sync works
    API
        POST /api/v3/invitation-links/{id} - Legacy auto-accept flow
        GET /api/v1/shoppinglists/polling - Syncs shared list data

COMPAT-02 | v6.5 user shares with v6.4 user - Backend auto-accept on polling
    Preconditions
        User A is on app version 6.5 (logged in, has active shopping list)
        User B is on app version 6.4.x (logged in)
    Actions
        User A opens their shopping list
        User A taps "Share" and generates a share link
        User A sends the share link to User B
        User B opens the share link (opens in browser or external handler)
        User B opens the REMA app and navigates to shopping lists
    Expected
        User B does not see invitation UI (v6.4 lacks this feature)
        The polling endpoint detects User B's v6.4.x user-agent
        The invitation is automatically accepted server-side during polling
        User B sees User A's shared shopping list appear in their lists
        User B can view and edit items in the shared list
    API
        POST /api/v3/invitation-links/{id} - Creates pending invitation
        GET /api/v1/shoppinglists/polling - Detects v6.4 user-agent and auto-accepts invitation
        GET /api/v3/users/{id}/shopping-list-invitations - Shows pending invitation before auto-accept
